# 有限弹药、换弹与战场补给

## 目标、基线与支持边界

目标用户为当前三分钟街区关卡中的本机浏览器玩家。原基线为二十四发弹匣、无限备用弹药、自动换弹时简单下压枪身。现在让弹药成为需要走位获取的有限资源，并明确提供缺弹、换弹、拾取和开箱反馈。

输入为当前士兵和步枪模型、五种敌人、现有街道碰撞和固定模拟时间。不调用模型服务，不增加付费生成任务，不改造成武器制造或真实枪械模拟。资源规则和状态由运行时确定性处理。

验收指标为：逐帧弹药守恒；零负弹药、零凭空装满、零隔墙拾取；提前换弹保留余弹；暂停不推进换弹；重开清除旧物件和声音；真实模型八方向动作误差小于三厘米；一条固定整局路线能够使用补给完成通关。误报、漏报和人工节省百分之八十不适用于游戏机制；没有测量人工节省比例，也不据此声称达到该门槛。

## 当前参数

| 项目 | 参数与行为 |
| --- | --- |
| 弹匣 | 二十四发 |
| 开局备弹 | 一百二十发，加上已装填弹匣，共一百四十四发 |
| 备弹上限 | 二百四十发，不含匣内子弹 |
| 换弹 | 一点七秒；空匣且有备弹时自动触发，也可按 R 或点界面按钮 |
| 余弹 | 提前换弹保留余弹，只从备弹取实际缺少的数量 |
| 部分装填 | 备弹不足一匣时仅装入剩余数量 |
| 战斗限制 | 换弹时可以移动，不能开火；无弹且无备弹时停止开火 |
| 普通敌人掉落 | 每次击败独立四成概率掉十二发，经验仍独立发放 |
| 首领掉落 | 必掉四十八发，同时保留首领经验 |
| 补给箱 | 每箱七十二发；开局随机放置三个，每四十五秒尝试补充一个 |
| 补给数量 | 同时最多三个尚有弹药的箱体；三分钟后不再新增 |
| 拾取 | 弹药在三米内吸引，在一点三五米内拾取；箱体在一点三五米内自动打开 |
| 溢出 | 超出备弹上限的部分留在掉落物或箱内；满备弹不消耗补给 |

补给箱从八个街道候选点中选择，同时检查障碍距离、玩家流场可达性和箱体间距。刷新遵循固定时间窗口，箱数已满时跳过该窗口，不累计空投。箱体不作为新增掩体。

## 动画、声音与界面

步枪继续使用原有材质和独立弹匣网格。换弹时轻微下压、侧倾枪身，左手转向弹匣，弹匣沿插槽取出约十五厘米后插回，随后左手完成枪机动作并回到护木。右手持续受握点约束；行走、瞄准、后坐和重新部署仍共用原角色根节点。

取匣、插匣和枪机声分别在换弹开始后的零点一八、零点九二、一点四秒触发。声音由短噪声和机械瞬态合成，不提前排队整段音频。拾弹、开箱和最后一发无备弹时另有提示。声音节点结束后释放；暂停、帮助、升级菜单、切换窗口和重开时清除正在播放及尚未开始的弹药音源。

弹药掉落为金色弹药包，经验继续使用绿色晶体。补给箱使用橄榄色箱体、金色绑带和地面识别圈，打开时掀盖，耗尽后淡出。所有拾取物共享几何和材质，清理时移除对应场景对象。

界面保留二十四格弹匣刻度，增加真实备弹读数、换弹动作和倒计时、R 按钮及拾取反馈。备弹不足或等于一匣时，显示最近补给箱相对于画面的方向与直线距离；障碍仍需玩家绕行。图标、按钮和状态行均处于正常文档流，使用弹性布局或网格换行，没有绝对定位。

## 自动验收

二零二六年十月二十五日，四十二项测试和生产构建通过。新增十一项覆盖有限总量、提前换弹与部分装填、声音时点、移动与暂停、断弹恢复、概率掉落与首领必掉、满备弹和部分拾取、隔墙限制、箱体刷新、渲染资源清理、真实弹匣行程及音源释放。原来的角色、弹道、掩体、敌人、升级和结算检查保留。

旧的绕圈路线不收集补给，有限弹药下会耗尽弹药。这是玩法改变后的预期结果。整局固定基准改为主动收集经验，低备弹时寻找补给，并沿可行走网格移动；仅增加生命以隔离生存难度，不额外注入弹药或伤害，强化使用实际可选择的伤害项。

该固定样本在一百八十秒完成通关：击倒一百三十六个敌人，射出二百七十七发，拾取三百八十四发，打开三个补给箱，结束时匣内十一发、备弹二百四十发。每一帧都检查：

```text
匣内弹药 + 备用弹药 + 已射出弹药 = 开局一百四十四发 + 实际拾取弹药
```

八方向移动与全向瞄准的真实模型回归共覆盖五千七百六十帧，换弹时双手目标误差小于三厘米，身体水平漂移小于一毫米。换弹结束或重开后，枪口恢复原挂点。

## 浏览器验收

本机内置浏览器验证了三发耗尽后停止射击、缺弹按 R 不凭空补充、靠近十二发掉落物自动换弹，以及靠近箱体补充七十二发并掀盖。换弹早期暂停时，剩余一点五六六七秒、游戏时间零点四八秒和声音计数在两次读取间保持完全一致，活动弹药音源为零；继续后完成后续动作。控制台未发现错误或警告。

分别查看了一千二百八十、七百、三百九十和三百二十像素宽度的实际界面，检查普通读数、三位备弹数、耗尽提示和按钮换行。三百二十像素下耗尽提示与 R 按钮分行，均留在弹药面板内部。截图与中文记录在 `.runtime/ammo/`；窄屏辅助页只用于本地验收，不进入生产构建。

开发地址的弹药验收参数只在开发构建生效，并且不保存成绩。正式进入游戏仍使用标准二十四发弹匣和一百二十发备弹。

## 审查

VERDICT: PASS

P0/P1 BLOCKERS: 无。

检查了换弹和开火互斥、备弹不足、装填完成帧、同时拾取多份弹药、满容量残留、箱体多次接触、隔墙吸引、可达位置、掉落与死亡结算、暂停和升级、胜负优先级、重开清理、音源节点及渲染资源生命周期、真实骨骼的移动与瞄准约束、界面窄屏和开发模式隔离。

反证检查确认：开火明确要求匣内大于零且换弹结束；装填仅转移实际可用备弹；每个死亡敌人只结算并移除一次；箱内弹药和掉落数量按实际转入量减少；满容量不清除箱体；拾取路径受视线和移动碰撞限制；补给受数量与时间窗口限制；换弹音效通过模拟跨过时间点触发，暂停不会继续推进；真实模型测试保留原精度门槛。未发现具有支持范围内可达触发路径且达到严重影响的阻塞问题。

UNVERIFIED RISKS: 普通难度下多名玩家、不同强化路线与随机种子的长期弹药平衡，以及不同设备和三十分钟稳定性尚未验收；合成机械声的主观听感未作人工听音验收。固定样本通过不等于所有玩家都不会缺弹。

NON-BLOCKING FINDINGS: 补给距离是直线提示，暂未显示绕墙导航路线；箱体不阻挡移动，开箱后短暂存在时可能与角色重叠；当前换弹为程序动作，后续如替换步枪模型，需要重新标定独立弹匣和手部目标。构建保留原有主包大于五百千字节的提示，不影响本轮功能通过。
