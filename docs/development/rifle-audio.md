# 步枪开火音色优化

日期：二〇二六年十月二十五日。

原方案由一段白噪声与下降音调的低频振荡器合成，约零点一二秒衰减，近远枪声只有固定音量区别。此次面向正常游玩的玩家，把步枪开火改为两次真实单发录音，目标是保留爆发前沿和自然尾音，避免重复音色、密集连发削波及暂停后残留。输入仍为现有枪口事件；没有修改伤害、弹道或射速规则。

## 录音与播放

素材为 AR-15／M4 步枪五点五六毫米实录，使用近距离爆响与少量中距离自然反射，经过裁剪、滤波和首尾淡化。两段零点九五秒的无损波形总计一百八十二点五千字节；[来源、授权与复现步骤](../../public/audio/rifle/README.md)随素材保存。

装备载入时并行下载并离线解码；开火直接播放缓存，枪声结束后释放临时节点。两段录音交替选择，并轻微改变音高和音量。玩家居中；敌方枪声按距离衰减音量和高频，按相对位置调整左右声位，并加入短距离传播延迟。共享动态压缩器控制密集开火的混音峰值。玩家和敌方各保留十六个声部，敌方饱和不会占用玩家预算。

暂停、菜单、重新开始、切出页面和图形设备断开时，音源快速淡出并停止；尚未到达的远处枪声同时取消。单段录音加载失败时继续使用另一段，全部失败时使用备用合成声，游戏仍可进入。

## 验证证据

固定随机种子，在本机 Chrome 中使用真实浏览器音频实现检查波形，并验证实际游戏接入。证据为项目内 `.runtime/rifle-audio/verification.json`；验证脚本为 `.runtime/rifle-audio/verify.mjs`。

| 样本 | 结果 |
| --- | --- |
| 单发、十六发最高射速连发、两百次同刻请求 | 均无削波和非有限样本；结束后声部归零 |
| 单发起音 | 离线图约七点五毫秒，包含混音前沿，不包含硬件输出延迟 |
| 最坏叠加 | 实际接纳三十二声部，峰值约零点六九一，保留输出余量 |
| 十六米右侧枪声 | 峰值约零点〇四九；右声道能量明显高于左声道 |
| 暂停与重复暂停 | 停止后无残留；尚未到达的远处枪声完全取消 |
| 四万四千一百赫兹输出 | 正常重采样，无削波，音源完整回收 |
| 实际游戏 | 记录十九次实录开火；暂停不增加音源，重开仍只使用一个实时音频上下文，页面脚本错误为零 |
| 一段或全部录音下载失败 | 游戏正常进入，分别播放剩余实录或备用音效 |
| 构建和回归 | 构建通过；当前工作区四十一项回归全部通过 |

试听文件为项目内 `.runtime/rifle-audio/preview.mp3`，依次包含单发、三发点射和八发连射，直接由同一播放链路的离线输出生成。

## 审查

VERDICT: PASS

P0/P1 BLOCKERS: 无。

反证检查覆盖：可选录音失败是否阻塞场景、首次开火是否额外请求网络、近远声部是否互相挤占、异步停止是否留下延迟枪声、重复暂停是否推迟停止、重开是否增加音频总线、自然结束是否断开全部临时节点，以及当前射速下的重叠声部和混音峰值。未发现成立的严重阻塞问题。

UNVERIFIED RISKS: 尚未完成其他浏览器、耳机和音箱的人工听感验收；当前证据不代表物理声学重建或硬件输出延迟测量。这些限制不影响本次结论。

NON-BLOCKING FINDINGS: 构建仍提示主包超过默认体积阈值；本次新增运行录音约一百八十二点五千字节，解码和下载均不在开火热路径上。
