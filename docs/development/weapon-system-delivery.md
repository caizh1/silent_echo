# 武器配件与手雷接入记录

日期：2026 年 10 月 25 日。

## 已完成的可玩流程

开局点击“装备配置”，选择手枪、冲锋枪或突击步枪。兼容配件可自由勾选，三维外观和属性同时更新。默认是标准手枪；手枪支持瞄具、弹匣和枪托，冲锋枪、突击步枪还支持前握把。进入战斗后配置锁定。暂停与结算页可用“更换装备”开始新行动；“重新部署”沿用当前配置并清空上一局状态。

瞄具减少百分之四十五散布，扩容弹匣增加百分之五十容量，枪托提高百分之十五射速，前握把减少百分之二十散布并提高百分之八射速。射速计时保留不足一帧的余量，避免六十赫兹步进吞掉小幅加成；长时间没有目标时不会积累待补发子弹。

每次行动三枚手雷，空格或手雷按钮主动投掷，长按不连投，冷却零点六五秒，引信一点二五秒。手雷沿当前瞄准方向飞行，近处目标采用短投；弹道连续检测三维墙体，可以越过低掩体，也能停在掩体顶面。爆炸对范围内且未被掩体遮挡的敌人造成伤害。暂停、升级和结算冻结投掷物，不接受新的投掷。

## 资源与费用

首选商店的模型下载需要登录，没有可用会话，因此实际采用 [Quaternius 的 CC0 模块化枪械](https://quaternius.com/packs/scifimodularguns.html) 与 [Kenney 的 CC0 Blaster Kit](https://kenney.nl/assets/blaster-kit)。新增手枪、冲锋枪、配件与手雷使用这些公开素材，突击步枪主体沿用已有模型。原始文件与原步枪母版保留；最终文件位于 public/models/weapons，按语义节点控制原装件与升级件互斥显示。

完整来源、摘要和加工说明见 [素材来源](../modeling/weapon-asset-sources.json)。源模型经裁切、配色、比例和挂点调整后导出 GLB。瞄具、枪托、弹匣和前握把均来自实际网格；预览由 Blender 与游戏渲染器绘制。本轮未使用 imagegen，未提交 Tripo 任务，未消耗 Tripo 积分。

可重复执行以下脚本，已下载的有效模型会复用缓存：

```sh
python3 scripts/download-weapon-models.py
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python scripts/prepare-weapon-models.py
python3 scripts/verify-weapon-integration.py
```

## 验收证据

全部五十二项自动检查通过，覆盖原有回归与新增武器、配件、手雷流程。三种真实武器共有四十种兼容配件组合，对八种移动方向、八种瞄准方向及三种换弹姿态共七千六百八十个样本进行检查，双手握点误差门槛为三厘米。枪口高度另对照真实枪管前端网格，不只比较两个配置常量。

固定目标的两组手枪弹道样本各发射一千二百发，未装瞄具命中率百分之六十五，安装后百分之九十九点九。该样本固定目标、弹药和射击调度，只验证散布改善，不代表正常难度、资源经济或移动目标下的长期平衡。

真实浏览器检查了三种武器切换、手枪禁用前握把、属性与外观更新、长按空格、飞行中暂停、重开和返回配置。长按一点五秒只投出一枚；第二枚投出后暂停，超过引信时间仍保持在飞状态；重开恢复三枚并清空旧投掷物。控制台未发现错误。三百七十五乘六百五十及七百乘四百八十的嵌入式窗口完成布局和可操作性目视检查，短窗口通过菜单滚动访问完整选项。

## 审查结论

VERDICT: PASS

P0/P1 BLOCKERS:

无。已对状态机、弹药一致性、投掷物碰撞、一次性伤害结算、输入焦点、资源生命周期、模型加载及共享角色接口进行审查，并反证核对已有保护机制。

具体保护路径包括：战斗开始后拒绝改装，读取配置返回副本；投掷先检查状态、数量和冷却，再扣数量；爆炸后移除投掷物，敌人死亡统一结算；空间碰撞同时考虑墙体高度与顶面；暂停和结算在推进模拟前返回；模型池固定三枚；预览复用同一个渲染器；未能创建预览时仍可配置和开始游戏。与同时新增的角色模块仅做场景类型和预览接口兼容修正，保留其功能。

UNVERIFIED RISKS:

- 长期正常难度平衡与三十分钟连续稳定性未验收。
- 嵌入式窄窗口检查不能代表物理手机性能与触屏操作。
- 尚无同批任务的完整人工耗时基线，不能宣称已经达到百分之八十人工节省。

NON-BLOCKING FINDINGS:

- P2：免费手枪、冲锋枪的硬表面细节比已有步枪更简化；已统一配色，进一步统一近景材质仍可改进。
- P2：手雷目前使用实际模型、弹道和爆炸表现，尚无专用投掷骨骼动画。
